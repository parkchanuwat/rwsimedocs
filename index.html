Why IME bugs happen

An input method editor sits between the keyboard and the text field. The app sees keys that are not yet text. Most IME bugs come from the app treating those in-between keys as if they were final.

The window replays real IME sessions: keys go to the IME, the draft is underlined while the IME owns it, candidates appear, and only the commit makes it final text.

Nine bug families to test for

Each links to the Bug Lab tests that reproduce it.

Hotkey leak

Space picks a candidate and plays the video

A single-key shortcut such as Space or 1 fires while the IME is using that key.

Navigation key leak

Esc cancels the draft and closes the dialog

Esc, Tab, arrows and Backspace edit the draft, but the app also closes a dialog, moves focus, steps a frame or deletes a clip.

Enter submits early

Enter confirms and sends the message

The Enter that confirms a conversion also sends the message or presses OK, or leaves a character behind.

Full-width leakage

１２０ ≠ 120

The IME produces ：, １２０, a full-width space (U+3000) or curly quotes where the field expects ASCII.

Lost composition

한글 → ㅎㅏㄴ

Moving focus, or re-rendering the field while you type, throws away or breaks the draft.

First key lost

きょう → kいょう

Type-to-rename opens the editor on the first key, before the IME sees it, so that key is dropped or stays a Latin letter.

Acts on draft text

search runs on mo'hu, not 模糊

Search, validation or a length limit runs on the unfinished draft: filtering on pinyin letters, or cutting the draft at a character limit.

Candidate window position

list opens in the corner, not at the caret

Custom-drawn, scaled or scrolled text fields send the IME the wrong caret position. Checked by eye.

Key code vs character

ㅠ ≠ b

Shortcuts matched by typed character fail when Hangul, Zhuyin or kana mode changes what the key reports.

Record in every IME bug

  • OS version and build
  • IME name and version. On Windows, whether “Use previous version of Microsoft IME” is on.
  • IME settings that change behavior: Live Conversion (macOS Japanese), predictive input, punctuation and space width
  • Keyboard layout: US, JIS or Korean
  • App build, and the browser or web view if the field is web-based

What to look for: an Enter keydown with isComposing=false right after compositionend (the Safari order), a composition that ends with empty data after Tab, or the last Korean syllable appearing twice.

The scenarios model common bug classes, not specific tracked bugs. Behavior varies by OS, IME version, browser and settings, so confirm on your own build before filing.

The labs assume a US QWERTY hardware keyboard. JIS and Korean keyboards work too: 半角/全角, かな and 한/영 do the same job as the switch keys listed.
