Why IME bugs happen

An input method editor sits between the keyboard and the text field. The app sees keys that are not yet text. Most IME bugs come from the app treating those in-between keys as if they were final.

The path from key to text

1 · KeysYou press n i h o n. The IME takes them first.
2 · CompositionUnderlined draft text appears: にほん. Nothing is committed yet.
3 · CandidatesA list offers matches: 日本 / 二本 / ニホン.
4 · CommitSpace, Enter, a number key or a click picks one. Only now does the field hold final text.

Event order is not identical everywhere. Safari, for example, can fire compositionend before the Enter keydown that confirmed the text, so an isComposing check that works in Chrome can fail there.

Six bug families to test for

Hotkey leak

A single-key shortcut such as Space or 1 fires while the IME is using that key to pick a candidate.

Labs: JA-1, KO-1, ZH-2

Enter submits early

The Enter that confirms a conversion also presses the dialog's OK button, or leaves a leftover character behind.

Labs: JA-2, KO-2

Full-width leakage

The IME produces ： １２０ or curly quotes where the field only accepts ASCII.

Labs: JA-3, ZH-1

Lost composition

Moving focus, or re-rendering the field while you type, throws away the draft text instead of keeping it.

Labs: JA-4, KO-4

Candidate window position

The list opens at a screen corner or far from the caret in scaled, rotated or custom-drawn text fields. Check this by eye in every text field type.

Lab: JA-5

Key code vs character

Shortcuts matched by typed character fail when Korean, Zhuyin or kana mode turns V into ㅍ.

Lab: KO-3

Everything here describes common behavior. Exact symptoms depend on the OS version, IME version, settings and the app's text engine. Treat each example as a pattern to try on your build and confirm before filing.

Hands-on · your real keyboard

Bug Lab

Eleven small test apps, one bug pattern each, matching the six families in Basics. Japanese and Korean come first. You type with your own IME, follow the numbered steps, and the page reads the real browser events to tell you whether the bug showed up. A bug report draft is built from the result.

Your computer:

You need the matching input source installed. Each lab lists the exact one, the layout and the mode. The labs assume a standard US QWERTY keyboard. A JIS or Korean keyboard works too: its extra keys (半角/全角, かな, 한/영) do the same job as the switch keys listed. Function keys and Ctrl or Cmd shortcuts need a hardware keyboard.
